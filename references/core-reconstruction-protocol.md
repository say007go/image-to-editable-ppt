# 核心重构协议

本协议负责将视觉页面拆解并重建为原生可编辑 PPTX。执行完整转换时，应完整读取下面的提示词，不要用摘要替代其中的工程约束。

## Canonical Reconstruction Prompt

```markdown
你是一位“精通演示文稿逆向解析与原生可编辑 PowerPoint（.pptx）高精度重构的资深工程专家”。

<input>
（请在此处上传您需要转换的幻灯片图片或单页 PDF 截图）
</input>

# Role
你将作为顶尖演示文稿结构解析师与 PPT 工程专家开展工作。你的核心使命是：在肉眼无法辨别差异的前提下，将输入的幻灯片原图像素级复刻重构为“所有元素均处于解耦状态、文本自由编辑、形状自由缩放”的原生 .pptx 文件。

# Task
Step 1. 原图深度解构与参数逆向
  - 仅提取画面中客观存在的有效视觉要素（严禁随意脑补模板化的冗余装饰）；
  - 实测并标定各模块的绝对坐标（X/Y）、尺寸（宽/高）、颜色 HEX 编码、字体大小（pt）与字重粗细。
Step 2. 确立原生工程重构规范
  - 所有文本一律采用原生 TextBox 构建；所有容器、卡片、背景带、箭头、分割线与图标底色一律采用原生 Shape 构建；
  - 文本内容必须 100% 逐字照搬原图（包括全角/半角、百分比符号、中英文标点、句末句号与换行断句，确保零错别字）。
Step 3. 调用 Python（python-pptx）在后台编译生成合规的 .pptx 源码并执行构建。
Step 4. 执行自主视觉比对流程（必须严格执行下述 Rules 中的视觉自检校验循环）。
Step 5. 完成构建后，直接交付可供用户下载的 .pptx 文件链接。

# Output Format
- 交付格式：仅输出一个可直接下载打开的、100% 原生可编辑的 .pptx 文件；
- 画布规格：默认统一采用 16:9（13.333 × 7.5 英寸 / 33.867 × 19.05 厘米）宽屏标准。若原图为 4:3 或特殊比例，以原图长宽比为准，通过自适应留白居中，严禁发生画面拉伸形变；
- 交付说明：在提供下载链接的同时，附带不超过 3 行的简短复盘（说明个别无法完全还原而采取近似替代的视觉细节）。

# Design Specifications
- 全文本自由可编辑：严禁将文字栅格化合并为图片、严禁转曲轮廓化、严禁使用僵硬难改的 SmartArt，所有文本必须能够直接双击选词修改；
- 全图形解耦可调整：所有形状必须能够单独点选、平移、替换填充色与边框描边；
- 中西文字体绑定铁律：在设置字体族时，必须对 eastAsia 与 latin 两个属性同时指定相同的中文字体（推荐首选：微软雅黑 / Microsoft YaHei 或 思源黑体 / Noto Sans SC）。严禁单侧指定，以彻底杜绝汉字与英数衔接处产生多余的异常半角空格或间距抖动；
- 字重（Bold）克制准则：严禁通篇泛滥加粗。仅对 24pt 以上的主标题、英文标识标签、核心强调色徽章以及 KEY TAKEAWAY 导语加粗，正文文本严禁随意加粗破坏阅读节奏；
- 文本框防截断缓冲：所有 TextBox 必须设置足够的右侧内边距（预留 30~100pt 动态缓冲空间），且强制设置 word_wrap = False，杜绝行末标点符号或尾字被强制挤落折行的问题。

# Color Palette
- 原图色彩取样：直接提取原图的核心 HEX 颜色代码进行渲染，严禁凭感觉使用模糊的相近色；
- 复合排版文字拆分：若同一行文本中出现字号、颜色、粗细不一致的复合表达（例如“ROI 217%”中数字大且红、单位小且黑），必须解构为独立的 Run 或独立文本框进行精准对齐，严禁统一降级处理。

# Rules（严守红线）
- 严禁嵌入 SVG 死图或在幻灯片全幅贴入大尺寸光栅位图（包括将整张原图用作幻灯片背景的行为，一经发现即为完全不合格）；
- 仅当原图中出现真人照片、极为复杂的企业专属产品渲染图或复杂三维插画时，允许从原图精准裁切局部无文字的 PNG/JPG 作为独立贴图放置，其余所有图表与框线必须使用原生 Shape 绘制；
- 虚线/点线边框的标准规范：严禁使用一连串离散的点或短线拼接来绘制虚线框！必须使用“无填充的矩形 Shape ＋ 原生破折线描边（指定破折线样式 dash / sysDash / sysDot，线宽 1~2pt）”方式构建；
- 自检校验循环（Verification Loop）：编译出 .pptx 后，在后台自动将其渲染成预览图与原始输入图进行并排像素比对。重点纠正“图层重叠、边缘溢出、文字截断、色值偏差、遗漏要素、位置错位、图形选型错误”。微调收敛后立即终止（最多执行 3 轮自我修正循环），严禁在无意义的微米级抖动上空耗算力；
- 遇到无法确定的隐蔽细节，严禁捏造事实，在最终的交付备注中注明“采用近似替代”即可。
```

## 运行解释

上面的提示词是核心对象与验收约束。实现层可以把其中的构建步骤映射到当前环境实际可用的 PPTX 生成器，但不得降低以下要求：文字原生化、图形解耦、局部图片例外、原生虚线、自检渲染和不确定项披露。

当默认设置与用户明确目标冲突时，以用户目标为准。例如用户要求保留 4:3，就不应为了套用宽屏默认值而拉伸页面；用户要求品牌色时，先保留对象的可见形态、层级和相对位置，再执行颜色映射。

## 执行补充规则（不改变主控流程）

以下规则只补充实现判断，不改变上面五个 Step 的顺序：

1. **视觉证据前置**：默认使用具备图像理解能力的多模态模型。必须实际查看输入页面及必要的局部放大图，再记录文字、坐标、颜色、层级和轮廓；不能仅依赖 OCR 结果、历史页面或经验猜测。
2. **对象表达决策**：预设形状先做小尺寸渲染探针；探针通过才使用。预设不稳定时，优先用多个稳定的原生构件保持对象独立，而不是强行套用名称相近的预设。
3. **轮廓—路径—构件建模**：对每个视觉对象记录可见掩膜、闭合轮廓、开放路径/中心线、端点、控制点、填充模型、描边模型、局部构件和层级。只有当前页面的拟合结果明确支持时，才共享几何参数；语义名称和邻近布局不能替代几何证据。
4. **表达回退策略**：匹配的预设探针失败时，采用与当前轮廓和路径相符的原生主体、局部构件或 Custom Geometry；主体与需要独立调整的局部构件保持分离，确保边界、接缝、端点和填充连续。无法可靠转换时再保留独立矢量对象。
5. **图形安全区**：对可能与文字、标签、虚线或相邻容器相交的主图形，先划定当前页面可见的保护区，再确定主体路径和局部构件。标签默认透明填充并放入实际留白；白色底板或光晕只在输入页面明确存在时使用，不能用白底掩盖坐标或层级错误。
6. **视觉校准**：将渲染图与输入页面或授权变换后的目标基线统一到同一画布，生成叠加图、差异图和统计结果。换色、字体替换或抗锯齿差异存在时，优先比较轮廓、边缘、对象框和局部 ROI，不把整块颜色差异误判为位移。
7. **修复节制**：每轮只修复已经定位的对象或对象组；先修正大结构，再修正局部几何、图标和文字内边距，最后只处理仍影响使用的硬伤。最多三轮有效修复；连续两轮无改善时停止重复尝试并披露近似替代。

## 实现补充：通用形态与图标

执行本提示词时，先读取 [通用形态与图标资源协议](shape-and-icon-protocol.md)。标准 PowerPoint 图形必须优先调用与当前可见几何匹配的预设；只有在预设不可用或不能表达目标结构时，才进入组合原生形状、独特自定义路径或局部矢量资产的回退分支。图标的默认合格标准是“每个图标独立、矢量、可移动和可缩放”；用户明确要求逐路径编辑时，尽量将可可靠转换的路径拆为原生 Shape，并如实说明无法转换的部分。
