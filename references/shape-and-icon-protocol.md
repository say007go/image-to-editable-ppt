# 通用形态与图标资源协议

本协议解决两个常见问题：视觉对象被错误套用为不匹配的标准形状，以及为了追求外观而把整页内容降级为不可编辑图片。它适用于图片或 PDF 页面中的规则图形、开放/闭合路径、复合结构、标准图标和局部矢量资产。

## 1. 轮廓—路径—构件重构机制

对每个视觉对象先建立当前页面的几何证据，再选择实现方式。语义名称、常见模板、相邻对象的排列方式和历史实现都不能替代可见轮廓。

| 优先级 | 实现方式 | 适用对象 | 主要验收点 |
|---|---|---|---|
| 1 | PowerPoint 预设 Shape | 与当前可见轮廓匹配的标准几何、开放路径、闭合路径或复合形状 | XML 中存在对应 `prstGeom`，对象可独立选中和调整 |
| 2 | 组合原生 Shape | 圆、矩形、线、曲线、连接线、轮廓与端部构件等复合结构 | 每个构件独立，接缝自然，线宽和对齐一致 |
| 3 | 独特自定义路径 | 预设库不存在的特殊轮廓，或预设在当前渲染适配器中无法稳定表达的视觉对象 | 每个复杂图形为独立原生 Custom Geometry，必须保留当前页面的真实轮廓 |
| 4 | 独立矢量资产 | 复杂但不承载文字的局部图标或标识 | 作为独立 SVG 对象插入并记录来源和许可证 |

### 1.1 几何证据记录

每个独立对象至少记录以下字段，字段值均来自当前页面的观察或拟合：

- `visible_mask`：对象的可见区域；
- `outer_contours`：闭合外轮廓、孔洞和缺口；
- `open_paths` / `centerlines`：开放路径、中心线和端点；
- `control_points`：曲线控制点、折点、圆弧关键点或其他拟合参数；
- `fill_model` / `stroke_model`：填充、描边、线宽、端点、连接方式、透明度和渐变；
- `local_components`：尖点、端部、阴影、高光、标记或其他可独立调整的局部构件；
- `z_order` 和 `uncertainty`：层级关系与尚未确认的细节。

### 1.2 表达方式选择

- 细长且以描边为主的对象，优先保留开放路径与描边属性；
- 面状且以填充为主的对象，优先保留闭合轮廓与填充属性；
- 同时包含主体和局部构件的对象，按可见子轮廓与层级拆分；
- 多个对象只有在当前页面的拟合结果证明其参数相同时，才共享样式或参数；共享样式不等于复制坐标、旋转或曲率；
- 预设、组合构件和自定义路径都必须以目标尺寸做局部渲染探针。主体与局部构件必须自然衔接，不能用后置遮挡掩盖边界错误；
- 对包含方向性端部、尖点或其他标记的对象，端部形态必须从当前可见轮廓拟合，不根据名称推断；
- 预设或组合方案仍不能保留特殊渐变、阴影、不规则尖端或路径轮廓时，再将确认过的矢量路径转为独立原生 Custom Geometry；离散采样只用于路径转换，密度必须足以避免肉眼可见折线；
- 不得把主要结构作为整页 SVG 或位图插入。

对任何可能与文字、标签、虚线或相邻容器相交的图形，先划定当前页面实际可见的保护区，再确定主体路径和局部构件；不要用白色文本框遮挡图形来制造“看起来没有重叠”的假象。

## 2. 标准图标资源

### 2.1 图标库选择与稳定调用

为了控制依赖复杂度，同时覆盖常见的线性、填充与多色图形，默认只维护三套候选图标库：

若用户明确指定其他开源图标库，且资源、版本和许可证可以追溯，应优先按用户指定资源执行同样的风格探针与来源记录；下表三套仅是未指定时的默认候选，不构成对用户选择的限制。

| 候选库 | 适合的视觉证据 | 官方/固定资源入口 | 许可证处理 |
|---|---|---|---|
| IconPark | 国内网络环境、需要线性/填充/双色/多色主题变体，或需要较丰富的业务语义覆盖 | [IconPark 官网](https://iconpark.oceanengine.com/official)、官方 SVG 包 `@icon-park/svg`、固定版本本地缓存 | 以所选固定版本随附的许可证文件为准；不要依赖在线入口的即时可用性，优先使用固定版本包或本地缓存 |
| Remix Icon | 输入页面明确使用同一语义的 line/fill 两种风格，或其具体图形与源图轮廓更接近 | [Remix Icon 官网](https://remixicon.com/)、官方仓库/固定版本资源、本地缓存 | 以所选固定版本随附的许可证文件为准；不得依据旧版本或第三方页面推断当前许可条件，也不得把图标单独打包售卖或当作品牌标志使用 |
| Lucide | 统一的简洁线性风格、需要稳定调节线宽和端点，或其他候选不可达 | [Lucide 官网](https://lucide.dev/)、固定版本 npm 包或本地缓存 | 以所选固定版本随附的许可证文件为准 |

候选库的顺序不是几何规则，也不是要求三套同时使用。先观察输入页面的线宽、端点、填充方式、视觉密度和语义覆盖，再在当前环境中探测资源可达性：

1. 在中国大陆网络环境且 IconPark 的包或缓存可用时，优先探测 IconPark；
2. 需要纯线性一致性时优先比较 Lucide 与 IconPark 的目标尺寸渲染结果；
3. 输入页面存在明确的线/面配对或 Remix Icon 的具体轮廓更接近时，选择 Remix Icon；
4. 若首选资源不可用，切换到下一套许可证清晰且风格匹配的候选，不改变页面结构，也不静默改用低分辨率 PNG。

同一页原则上只使用一个图标家族；只有输入页面明确呈现多个家族，或用户明确要求，才允许分家族使用，并在对象清单中记录边界。网站只用于检索和人工确认，实际编译优先使用固定版本、本地包或缓存 SVG。每个实际使用的图标都要保存 `library`、`icon_id`、`version`、`license_url` 或许可证文件位置、`viewBox`、`stroke_width`、最终颜色和 SVG 内容哈希；必要时把 SVG 与许可证说明一并放入任务资源目录。

### 2.2 图标对象规范

每个图标都必须满足：

- 独立占用一个可定位的对象框，不与文字或卡片背景合并；
- 记录 `library`、`icon_id`、版本、许可证、`viewBox`、`stroke_width` 和最终颜色；
- 同一图标家族中处于同一视觉角色和尺寸范围的图标，保持可确认的线宽、端点、连接方式和视觉尺寸；
- 优先使用 SVG 或其他矢量格式，禁止为了简单而转成低分辨率 PNG；
- 图标只承载视觉语义，不承载必须逐字编辑的文字、数据表或主要结构；
- 对品牌色变换时，优先改变 SVG 的 `stroke` / `fill` 或矢量对象颜色，不改变图标几何。

### 2.3 图标的编辑边界

默认采用对象级可编辑：每个 SVG 是一个独立的 PPT 矢量对象，可以移动、缩放、替换或在运行环境支持时换色；不声称 SVG 内部每条路径均可单独选中。

如果用户明确要求路径级编辑，则将运行环境能够可靠解析的基础几何基元和路径段拆为原生 Shape；无法稳定转换的复杂路径仍保留为独立 SVG，并在验收说明中注明。不能为了增加 Shape 数量而牺牲图标轮廓质量。

## 3. 运行环境适配接口

运行环境至少应提供或声明以下能力：

```text
supports_preset_geometry(name) -> boolean
add_preset_shape(name, position, style, adjustments) -> native shape
add_path_body(path_or_contours, position, style) -> native shape
add_path_terminal(terminal_geometry, position, style) -> native shape
add_composite_shape(components, position, style) -> independent native shapes
add_vector_icon(svg_bytes, position, style, metadata) -> independent vector object
convert_vector_icon_to_native(svg_bytes) -> native shapes | unsupported
convert_vector_path_to_native(svg_path, position, style) -> native custom geometry | unsupported
```

对每一种实际使用的预设或路径构件，都要先以当前页面的目标尺寸、可见轮廓和局部关系做渲染探针，验证主体边界、局部构件、填充方向和安全区；探针通过才使用预设，探针失败时登记失败证据并选择匹配的组合原生对象或 `convert_vector_path_to_native`。任何具体预设都只是候选实现，不能反过来决定对象的几何类型。若首选图标库不可用，改用另一套许可证清晰且风格统一的矢量图标库；没有矢量能力时不得静默降级为低分辨率 PNG。

## 4. 稳定性验收

一套方法只有同时通过以下检查，才能作为默认实现：

1. 实际选用的预设、组合图形或自定义路径在目标环境中能稳定渲染；每个回退方案都必须先通过自己的探针或局部叠加验收；
2. 页面中确实重复的对象在对应对象之间保持可确认的线宽、端点、接缝和视觉比例；每个对象的轮廓、路径和位置仍以当前页面证据为准，不因追求同构而机械复制；
3. 同一图标家族中处于同一视觉角色和尺寸范围的图标，在不同尺寸下保持可确认的线宽、端点和视觉尺寸关系；
4. 使用预设时，PPTX 包中存在对应 `prstGeom`；使用图标时，资源保持独立矢量类型；
5. 结构检查、渲染检查和实际编辑抽查的结果分别记录，不把“能渲染”误称为“路径级可编辑”；
6. 预设或 SVG 能力不足时，触发已登记的回退规则，而不是静默改变对象类型；
7. 回退路径必须通过输入页面/渲染图透明叠加检查，图形的实际可见轮廓不得覆盖当前页面中未被输入证据授权相交的受保护文字、标签、虚线或相邻容器。

## 5. 推荐的对象命名

```text
shape-{object-id}-body
shape-{object-id}-local-component
shape-{object-id}-custom-path
shape-{object-id}-preset
icon-{object-id}-{library}
```

命名中保留对象标识和实现类型，便于结构审计、局部替换和缺陷修复；命名不应出现在用户可见的页面文字中。
